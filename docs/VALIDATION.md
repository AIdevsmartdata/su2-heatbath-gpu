# Validation

This page lists what has been checked, with the numbers, and what has not. Criteria of the test
suite were frozen before its first run (`tests/CRITERIA.md`). Seeds are fixed: on a given machine
and build, every result below is reproduced exactly by re-running the same command.

## 2. Bit-level anchors to archived runs

`make anchor-hip` / `make anchor-cuda` re-run one archived chain and compare sha256 sums
(`tests/anchors.sha256`).

- **HIP**: with HIP 7.1 / clang 21.1.8 and the Makefile command line, `src/su2_hip.cpp` compiles
  to a binary with sha256 `d62ff7d2a9cfc861…`, byte-identical to the binary that produced 84
  validation and production chains in September 2026. The source used then differs from the
  published one only in its comments (translated into English, internal notes removed, line
  numbers kept; the comment-free code is identical byte for byte), which is why the binary is
  unchanged. The chain
  L = 12, beta = 2.5, seed 26095612011 (5000 + 2000 steps) is regenerated byte for byte
  (`cfg_002000.npy`, `measurements.csv`, `therm.csv`).
- **CUDA**: with nvcc 13.3 for sm_120, the chain L = 8, beta = 2.8, seed 27092708011
  (2000 + 20000 steps) of the CUDA port validation of September 2026 is regenerated byte for byte.
  The binary itself cannot serve as an anchor: two nvcc compilations of the same file gave two
  different binaries.

These anchors only hold on the same GPU architecture with the same compiler and runtime versions;
elsewhere the outputs differ in the last bits and then decorrelate (T8), and the statistical tests
are the relevant ones.

## 3. Same seed on two back-ends does not give independent chains

The HIP, CUDA and CPU (`su2_omp`) programs draw identical random numbers for identical arguments.
After a few steps their configurations differ at the byte level (T8), yet the chains remain
statistically correlated because the same random numbers keep driving them: for the T3 runs (same
seeds on both GPUs, 10000 measurements) the correlation coefficient between the HIP and CUDA
plaquette series is +0.48 at beta = 2.3 and +0.58 at beta = 2.5; it is +0.56 for the T2 runs at
beta = 0.5. Results obtained with the same seed on two back-ends must therefore not be combined as
independent measurements. Use different seeds for independent chains. No test of the suite
compares two such chains with each other: T3 compares with archived values produced with other
seeds, T4 and C2 with a code that uses a different generator.

## 4. The strong-coupling value used by T2

With the character expansion e^{(beta/2) Tr U} = c₀ [1 + Σ_{j≥1/2} d_j a_j χ_j(U)], d_j = 2j + 1,
a_j = I_{2j+1}(beta) / I₁(beta), the fundamental coefficient is u = a_{1/2} = I₂(beta)/I₁(beta)
(u = beta/4 − beta³/96 + ... at small beta). The lowest orders of the plaquette expectation value in
four dimensions are

    < ½ Tr U_p > = u + 4 u⁵ + O(u⁵ a₁, u⁷).

The leading term comes from the plaquette itself; the u⁵ term comes from the closed surfaces of
the 4 elementary cubes that contain a given plaquette in four dimensions (each closed surface of
fundamental plaquettes with Euler characteristic 2 contributes a^{F−1} relative to the observable,
F = 6 faces). We derived these two terms ourselves for this test and have not checked the u⁵
coefficient against a published series; the test does not depend much on it: at beta = 0.5,
u = 0.1237179 and 4u⁵ = 1.16·10⁻⁴, while the pass window of T2 is about ±1.8·10⁻⁴ (4 sigma) for
the GPU runs; with the values measured on 25 October, any coefficient between about −3 and +9
would have passed. The neglected terms are estimated at a few 10⁻⁶ (for instance 12 a₁ u⁵ = 3.6·10⁻⁶ and −16 u⁷ = −7.1·10⁻⁶); the test adds a theory error of
50 u⁷ = 2.2·10⁻⁵. Finite-volume corrections at L = 6 (surfaces wrapping the lattice) are of order
u²⁴ and negligible. What T2 really pins down is the normalisation of the action: a factor 2 in beta
would move the plaquette by about 0.12.

The data favour u + 4u⁵ over u alone (z against u alone: +2.2 for the HIP run, +1.3 for the
independent Metropolis run), but the u⁵ term is at the edge of what these short runs resolve.

## 5. Earlier validation (September 2026, not reproducible from this repository alone)

The same source (up to comments, see §2) was validated in September 2026 on the AMD machine, and
its CUDA port one day later on the NVIDIA machine, with criteria frozen before the runs. The
reports and the ensembles (84 chains, 1560 dumps) are not part of this repository; the numbers are
quoted here for information.

- Sampler test: the same 7 values of alpha as T1, max |z| = 2.11 (identical moments to today's T1,
  as expected from the identical binary).
- Plaquette against an independent single-threaded CPU Metropolis code (not published), L = 6 and
  8, beta = 2.3 and 2.5: z = +0.39, −1.02, +0.59, +0.54.
- Plaquette against Athenodorou and Teper (JHEP 12 (2021) 082, Tables 1 and 12, interpolated at
  beta = 2.3 and 2.5), where finite-volume effects are negligible (L·sqrt(sigma) ≥ 3):
  L = 16, beta = 2.3: −0.18 sigma; L = 24, beta = 2.3: −0.33 sigma; L = 24, beta = 2.5: +0.46 sigma;
  and one case above 2 sigma, L = 12, beta = 2.3: +2.14 sigma (difference 8.3·10⁻⁵).
- At L = 6 the plaquette differs from the infinite-volume value by a finite-volume effect,
  +7.0·10⁻⁴ at beta = 2.3 (13 sigma at the precision of the GPU runs) and +9.3·10⁻⁴ at beta = 2.5.
  This is why the L = 6 tests of this repository compare with L = 6 values and not with the
  literature.
- Unitarity of all 1560 dumps: max |UU⁺ − 1| ≤ 6.7·10⁻¹⁶; the plaquette recomputed from the dumps
  agrees with the GPU value.
- CUDA port: the plaquette at L = 6 and 8, beta = 2.3, 2.8 and 3.5 (6 cells, 3 chains each,
  different seeds on the two machines) agrees with the AMD results, chi² = 4.53 for 6 degrees of
  freedom (p = 0.61); Kolmogorov-Smirnov permutation tests on the local plaquettes at beta = 2.8:
  p = 0.23 (L = 6) and 0.68 (L = 8).

## 6. What has not been validated

- GPUs other than the two above, other compiler versions, other operating systems.
- Observables other than the plaquette and the Polyakov loops written by the program (no Wilson
  loops, topological charge, glueball or potential measurements are provided or validated here).
- Couplings outside the tested range: the test suite uses beta = 0.5, 2.3 and 2.5 (and the sampler
  alpha up to 100); the September 2026 production used beta from 2.3 to 16. beta = 0 is not
  supported (see README).
- Long-run behaviour beyond the measured autocorrelation times, and lattices larger than L = 32.
- Robustness against hardware faults: see the README section on silent data corruption.
